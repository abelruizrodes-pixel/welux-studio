# WELUX STUDIO // Luxury Digital Growth, Creative Lab & Cinema Rentals

> **Luxembourg • Madrid • Paris**  
> Plataforma digital oficial de **Welux Studio** y división técnica **Amcropa Films**.

## 🏛️ Descripción del Proyecto

**Welux Studio** es una plataforma web moderna tipo Single Page Application (SPA) ultra-optimizada, diseñada bajo los principios del *Quiet Luxury* y la excelencia visual europea.

Incluye 6 universos creativos, demostraciones interactivas en vivo, catálogo de material cinematográfico profesional y calculadoras de presupuestos en tiempo real.

## 🚀 Despliegue en GitHub Pages

1. **Crear repositorio en GitHub**:
   ```bash
   git init
   git add .
   git commit -m "Initial commit: Welux Studio official app with 360 Virtual Tours"
   git branch -M main
   git remote add origin https://github.com/TU-USUARIO/welux-studio.git
   git push -u origin main
   ```

2. **Activar GitHub Pages**:
   - Entra en tu repositorio en GitHub > **Settings** > **Pages**.
   - En **Source**, selecciona `Deploy from a branch`.
   - Selecciona la rama `main` y la carpeta `/ (root)`.
   - Haz clic en **Save**. En 1 minuto tendrás tu web online con HTTPS gratuito.

## 📘 Referencia viva del proyecto

La estructura viva hoy es multi-página por idioma, como se describe abajo. En caso de contradicción, manda esta sección.

### Qué es este repo

- Fuente de **weluxhub.com**, publicada con **GitHub Pages** desde la rama `main`.
- Sitio multi-página por idioma: el español vive en la raíz (`index.html`, `gear/`, `films/`, `studio/`, `careers/`) y las demás lenguas en sus carpetas: `en/`, `fr/`, `de/`, `pt/` y `lu/`.
- Secciones principales: **Gear** (alquiler de material de cine), **Films**, **Studio** y **Careers**.
- Script central: `assets/js/welux-v2.js` (efectos, parallax, vídeo del hero y botón de cambio de idioma). Las páginas comparten la misma base de estilos con Tailwind.

### ⛔ REGLA DURA — Tema claro (no es un error)

- `assets/js/welux-v2.js`, línea 17: `document.documentElement.classList.remove('dark')` quita el modo oscuro al cargar la página. El tema claro es deliberado.
- Las plantillas declaran `<html class="dark">` y Tailwind está configurado con `darkMode: "class"`. Esa combinación es intencional: el tema claro se fuerza por script al cargar.
- **No quitar ni «arreglar» esa línea ni el `class="dark"` del `<html>`.** Quien la lea como un error está equivocado: es el comportamiento querido del sitio.

### ⛔ REGLA DURA — Datos personales (nunca en el código público)

- Nunca publicar en este repo público: dirección particular, teléfono, WhatsApp, RCS ni pólizas.
- Único contacto público: **info@weluxhub.com**.
- El RCS solo va detrás de la puerta de datos del aviso legal; nunca en el código público.

### Sin paso de compilación

- Tailwind se carga por **Play CDN** (`cdn.tailwindcss.com`); no hay `package.json` ni `tailwind.config.js` (la configuración de Tailwind vive en línea en cada página).
- Las páginas parecen generadas por scripts (`generate_multilingual_complete.py`, `build_full_multilingual_ecosystem.py` en la raíz): **no regenerar**. Regenerar reintroduce la dirección, el teléfono y el WhatsApp que ya se quitaron a mano.
- Los cambios se hacen editando directamente los archivos HTML en `main`.

### Backend

- **Worker `weluxhub-api`** + base de datos **D1 `welux-leads`** (ver carpeta `worker/`).
- Los formularios guardan los envíos en D1.
- Notificaciones por correo con **Resend** (secreto `RESEND_API_KEY`, nunca en el repo) o **MailChannels** como respaldo.

### Despliegue

- **GitHub Pages**: cada push a `main` lanza un despliegue nuevo y cancela el despliegue anterior.
- Durante la propagación, el CDN puede mezclar versiones viejas y nuevas: **verificar en vivo solo al final**, cuando el despliegue de ese push haya terminado.

### Vuelta 16 (9 nov 2026)

- **Careers EN** (`en/careers/index.html`): la fila interna de la cabecera rebosaba ~40 px y dejaba visible la barra de desplazamiento horizontal bajo la cabecera (el documento no se desplazaba). Se añadió un `<style>` en ese archivo: la fila y el `nav` envuelven en dos líneas y se quita el desplazamiento horizontal.
- **Gear ES/FR** (`gear/index.html`, `fr/gear/index.html`): el HTML del catálogo está completo en `main` (`#catalogo` con el kit y las tarjetas), pero `assets/js/welux-v2.js` lo oculta: el bloque «ocultar por secciones» pone `display:none` a todas las `<section>` de `main` salvo el héroe y solo las muestra al pulsar una tarjeta; los enlaces del menú (`#catalogo`, `#fotomaton-glam`, `#talent-lab`) no las revelaban. En cada archivo se añadió un `<style>` con `main section{display:block!important}` para que el catálogo se vea al desplazar.
- **Línea del kit**: «Kit de Cine Listo para Rodar • $425 / día» / «Kit Cinéma Prêt à Tourner • $425 / jour» existe en el HTML estático tras el `h3` del rig, pero la versión servida en vivo no la renderizaba. Las páginas Gear cargaban un `welux-v2.js` sin la inserción de `fixRig` (vuelta 12): ES tenía `?v=10` y FR no tenía versión; en ambas se subió a `?v=13` para servir el JS actual.
- **Despliegue**: el sitio vive en Cloudflare Pages (proyecto «weluxhub», https://weluxhub.pages.dev); GitHub sigue como fuente del código. La verificación en vivo se hace tras el despliegue en Cloudflare.


### Vuelta 17 (9 nov 2026)

- **Motivo**: tras pasar a Cloudflare el sitio se veía desnudo (sin CSS ni JavaScript aparentes, solo el home visible), aunque la comprobación desde el servidor daba 200 en CSS, JS, Tailwind y todas las páginas. La verificación en vivo a 1920 px mostró que el home cargaba con estilos, pero Gear y el resto de divisiones quedaban pálidas o con solo el héroe visible: el problema era de renderizado, no de archivos ausentes.
- **Causas** (en `assets/js/welux-v2.js`): el reveal deja las secciones en opacidad 0 hasta 4 s o hasta hacer scroll; la «simplificación radical» oculta con `display:none` todos los hijos de `<main>` salvo el héroe y oculta los `<p>` del héroe salvo el primero — ahí cae la línea del kit tras el `h3` del rig, por eso ni el HTML estático ni `fixRig` (vuelta 12) la hacían visible —; y el bloque «ocultar por secciones» oculta todas las `<section>` de Studio/Gear salvo el héroe y oculta el `nav`.
- **Arreglo global** (`assets/js/welux-v2.js`, nueva versión canónica `?v=14`): bloque nuevo al final del archivo, con red de seguridad en `load` y a 600/1500/3000 ms: revela todo rápido (fundido de 0,35 s), muestra las secciones de Studio/Gear, vuelve a mostrar la línea del kit (con su texto por idioma) y el `nav`, y quita la barra horizontal de la cabecera de Careers. No toca la línea 17 (tema claro deliberado).
- **Gear EN** (`en/gear/index.html`): mismo arreglo que ES/FR en la vuelta 16 (`<style>` con `main section{display:block!important}` antes de `</head>`) y script subido a `welux-v2.js?v=14`.
- **Gear ES/FR** (`gear/index.html`, `fr/gear/index.html`): script de `?v=13` a `?v=14` para servir el JS actual; el estilo con `main section{display:block!important}` ya estaba desde la vuelta 16.
- **Careers EN** (`en/careers/index.html`): la regla `header aside>div` de la vuelta 16 era código muerto — el `<aside>` es hermano de `</header>`, no hijo —. Se añadieron las reglas de la vuelta 17 (`header{overflow-x:clip!important}` y `header+aside>div,body>aside>div` con `flex-wrap`) en el mismo bloque `<style>`, y el script se subió a `welux-v2.js?v=14`.
- **Studio**: recoge el arreglo global en JS al desplegar, sin tocar sus HTML en esta vuelta; si la caché sirve una versión antigua con `?v=10`, se subirá a `?v=14` en la siguiente vuelta.
